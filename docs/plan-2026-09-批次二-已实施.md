## A. 厂商健康监控 + 通知

**internal/health/health.go**：
- `Monitor` 结构：持 registry 引用；`Start(interval)` 起循环 goroutine，逐个**启用中** provider 探活
- 探活方式 = 各自的模型列表接口（不发消息不花钱）：gw→`FetchModelsRaw`；openai/anthropic→`FetchModels`；gemini→新加的模型接口（见 C）。成功=up，记录 latencyMs；失败=down，记 consecutiveFails
- 状态表：`map[providerID]Status{State, LatencyMS, LastCheck, LastError}`（RWMutex）
- **状态翻转时**（up→down / down→up）：回调 onChange(provider, state)——app.go 里发 Wails 事件 `health:change` + `runtime.SendNotification`（需先 `InitializeNotifications`，wailsjs runtime 已有）
- config 加 `HealthEnabled bool`（默认 true）、`HealthIntervalSec int`（默认 300，下限 60）

**app.go**：startup 里构建并按配置启动；绑定 `GetHealth()`（返回全部状态数组）
**前端**：Dashboard 顶部「厂商健康」卡片（每厂商一枚灯：🟢up/🔴down + 延迟 + 检查时间，点击跳转厂商页）；Providers 列表行内状态徽标；health:change 事件刷新

## B. 录制文件浏览器

**app.go 绑定**（复用 recorder 的 RecordDir 配置）：
- `ListRecordings()`：扫描目录 `llm-record-*.jsonl` → `[{date, sizeBytes, lines}]`（行数读文件数 `\n`，文件 MB 级可接受）
- `ReadRecordings(date, keyword, maxEntries)`：逐行解析 JSONL（recorder.Entry 结构），keyword 过滤（匹配 body/model），每条 body 截断至 4000 字符，返回倒序数组
- `DeleteRecording(date)`：删指定文件

**前端**：新页「📁 录制浏览」（nav 项）：左列文件列表（日期/大小/行数/删除按钮）；右侧选中文件的内容流（req/resp 分色卡片：方向徽标、时间、模型、transform 标记、body 预览 pre）；顶部搜索框 + 刷新。入口：Logs 页录制卡片加「浏览…」按钮跳转。

## C. Gemini provider（完整：对话/工具/流式）

**协议要点**（已核实）：端点 `POST {base}/v1beta/models/{model}:generateContent`（非流式）/ `:streamGenerateContent?alt=sse`（流式）；header `x-goog-api-key`；模型列表 `GET {base}/v1beta/models`（`{models:[{name:"models/gemini-..."}]}`，去 `models/` 前缀）。

**config.Provider.Type 加 "gemini"**（Registry.Rebuild 加 case）。

**internal/provider/gemini.go**：Do 按上述端点转发（body 已是 gemini 格式）；FetchModels 拉模型列表。

**internal/transform/gemini.go**（OAIChat ↔ Gemini 双向）：
- 请求：system→`systemInstruction.parts[].text`；assistant→`role:"model"`；assistant.tool_calls→model turn 的 `functionCall` part；`role:tool`→user turn 的 `functionResponse{name,response}` part（arguments JSON 串↔response 对象）；tools→`tools[].functionDeclarations[{name,description,parameters}]`；max_tokens/temperature→`generationConfig{maxOutputTokens,temperature}`；stop→`stopSequences`
- 响应：`candidates[0].content.parts`（text join / functionCall→tool_calls）；finishReason `STOP/MAX_TOKENS→stop/length`；`usageMetadata{promptTokenCount,candidatesTokenCount}`→prompt/completion
- 流式：**G2O**（gemini SSE→chat chunk 流：每 data 行一个完整 GenerateContentResponse，text part→content delta、functionCall part（全量 arguments）→单 chunk tool_calls、末尾合成 finish+usage chunk+[DONE]）；**O2G**（chat chunk→gemini SSE：text delta→`{candidates:[{content:{parts:[{text}]}}]}` 帧，finish 时发含 usageMetadata 的收尾帧）
- gemini 在 Protocol() 上归为独立 `ProtocolGemini`；needTransform 判定自动生效（gemini 上游 × openai/anthropic/responses 客户端全组合经 openai-chat 中间表示串联）

**Providers.vue**：类型下拉加「Gemini（Google AI Studio）」，提示 baseURL 填 `https://generativelanguage.googleapis.com`。

## D. /v1/responses 端点（Responses → 全厂商）

范围：**Responses 客户端 → 任意上游**（Codex CLI 等可调全部厂商）。反向（chat 客户端调 responses 上游）不做。

**路由**：`POST /v1/responses`（+`/responses`）→ `handleChat(w, r, ProtocolResponses)`。

**transform/responses.go**：
- `ResponsesReq → OAIChatReq`：`instructions`→首条 system 消息；`input`（字符串→单 user 消息；数组 items：`message{role,content[input_text/output_text]}`→消息、`function_call{call_id,name,arguments}`→assistant.tool_calls、`function_call_output{call_id,output}`→tool 消息）；`tools[{type:function,name,parameters}]`→chat tools；`max_output_tokens→max_tokens`；tool_choice 字符串映射复用现有
- `OAIChatResp → ResponsesResp`：output 数组 = message item（output_text）+ function_call items（call_id=id）；`status:"completed"`；usage 映射
- **流式 R2 流转换器**（chat chunk 流→Responses 事件流）：`response.created` → `output_item.added(message)` → `output_text.delta`（逐 content 增量）→ tool_calls→`output_item.added(function_call)`+`response.function_call_arguments.delta` → `output_item.done` → `response.completed`（含完整 usage）。事件帧格式 `event: <type>\ndata: {...}\n\n`

**handlers.go 改造**：`clientProto` 增加第三值 `responses`；convertRequest/convertResponse/streamConverted 的转换矩阵扩展——responses 客户端：请求先 Responses→OAIChat，若上游为 anthropic/gemini 再套现有 O→A / 新 O2G；响应反向同链。日志/录制/failover/统计对 /v1/responses 全部自动生效（已有管道参数化）。

## 风险（实施时均已处理）

- Gemini role 语义（仅 user/model）映射边角：单测覆盖往返
- Responses 的 stateful 特性（previous_response_id、内置工具）v1 不支持——返回明确 400 错误说明
- Codex 对事件序列的严格性：实现最小完整集
- 通知权限：失败时静默降级为应用内 toast
